### SmartFactoryV2 — 다품종 생산순서 최적화 의사결정 지원 시스템 (2026.05)

- 대회: 2026 스마트 공장 운영 시스템 MVP 개발 해커톤 (차세대융합기술연구원 메이커스페이스 × DACON)
- 결과: **163팀 중 본선 진출** (2026.05.22 오프라인 본선)
- 팀: 2인팀 (팀 타르트포인트) — 담당: 백엔드·AI/ML·DB
- 기술: 백엔드(Python, FastAPI, Pydantic, XGBoost, OR-Tools, SQLite) / 프론트(React 18, Vite, TypeScript)
- GitHub: [github.com/Ease113/Feel-the-vibe](https://github.com/Ease113/Feel-the-vibe)

**설계 판단**
1. **비결정적 연산 분리를 위한 API 계약 설계** — 화면 조정 시마다 OR-Tools 재호출되면 비교 기준선이 흔들림. `/optimize`는 진입 시 1회만 호출하여 추천 순서를 고정하고, 조정은 경량 `/predict`로 분리.
2. **계층형 Fallback 설계** — API 키 누락·모델 미학습·라이브러리 오류 시 파이프라인 정지 위험. XGBoost → 휴리스틱, OR-Tools → 근사 탐색, LLM → 템플릿으로 단계별 다운그레이드.
3. **데이터 모델 모호성 제거** — 한 생산 계획 내 동일 SKU 중복 배치 가능. 순서 식별 키를 `sku_id` 대신 고유 `plan_item_id`로 정의.

**개발 환경**
- 자체 정립한 AI-assisted Workflow (Claude Code / Codex) 적용
- 설계 문서 선행 → 구현 → 교차 검증 순서로 진행
- `CLAUDE.md`로 자연어 규칙(가정 명시·범위 통제·Surgical Changes) 명문화
- `design-doc.md` 템플릿(Context / Goals & Non-Goals / Architecture / Sequence / Decisions / Edge Cases)으로 구현 전 게이트웨이 운영

## AI-assisted Engineering 워크플로우 정립 과정 (참고용)

> 이력서에는 SmartFactory 안의 "개발 환경" 한 단락으로 압축 편입됨. 자세한 맥락은 여기 보관.

**1단계 — GeminiFactory (Gemini + MCP + CLI)**
PMO 산출물(요구사항 정의서, 시스템 설계서 등) 자동화를 위해 Gemini 기반 MCP·Skill 구성, 템플릿·아웃풋·컨텍스트 구조 정의 CLI 환경 직접 구축. Gemini 성능 한계 확인 후 동일 구조를 Claude로 이식해 산출물 자동화 일부 구현 성공.

**2단계 — PMO-Assistant (Codex 기반 오케스트레이터)**
design → dev → review → PR 하네스 위에 오케스트레이터 구현. CMD 백그라운드에서 24/7 자율 실행. Reviewer 단계에서 Claude ↔ Codex 교차 검증, 최종 검토만 사람.

**3단계 — 한계 발견과 중단**
구현이 진행될수록 시스템이 초기 설계 범위를 스스로 확장하는 문제 발견. 매 단계의 확장이 국소적으로는 합리적이라 멈추기 어려움. 핵심 문제가 "AI가 코드를 생성할 수 있는가"가 아니라 "구현이 초기 의도 안에 머무를 수 있는가"임을 확인하고 자율 구현 중단.

**현재 — 규칙·템플릿 기반으로 전환**
복잡한 오케스트레이터 대신 명시적 규칙(`CLAUDE.md`)과 설계 문서 템플릿(`design-doc.md`)으로 구현 범위 제어. 결정론적 검증 가능한 항목은 린터에 위임, 자연어 규칙은 도구가 잡을 수 없는 영역(가정 명시·범위 통제·설계 판단)에만 집중.
